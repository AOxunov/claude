# Сессия 2026-08-06

## Проект

`spring-accounting-api` — REST API на Spring Boot + PostgreSQL (Neon).

## Что разобрали

### Структура проекта
- 3 слоя: Entity → Repository → Controller
- Подключена облачная БД Neon (PostgreSQL)

### Employee.java — JPA Entity
- Аннотации: `@Entity`, `@Table`, `@Id`, `@Column`, `@JdbcTypeCode`
- Типы данных: `UUID`, `LocalDateTime`, `Map<String, Object>` (JSONB)
- Инкапсуляция: поля `private`, доступ через геттеры/сеттеры
- Обязательный пустой конструктор для JPA

### EmployeeRepository.java — Spring Data JPA
- `interface`, не class — Spring сам создаёт реализацию
- `extends JpaRepository<Employee, UUID>` → бесплатные методы: findAll, save, deleteById и др.
- Generics `<Employee, UUID>` — безопасность типов

### EmployeeController.java — REST Controller
- `@RestController` + `@RequestMapping` — базовый URL
- `@GetMapping` / `@PostMapping` — HTTP-методы
- `@RequestBody` — читает JSON из тела запроса
- Dependency Injection через конструктор (рекомендуемый стиль)
- `private final` для зависимостей

## Найденные баги/проблемы

1. **Опечатка в сеттере** (`Employee.java:105`): метод называется `setUpdated_by` вместо `setUpdatedBy`. Нарушает соглашение именования Java (camelCase). Jackson/JPA может не найти этот сеттер.
2. **Пароль в application.properties** открытым текстом — в реальном проекте нужно использовать переменные среды (`${DB_PASSWORD}`).

## Что понял

- Entity-класс = таблица в БД, объект = строка
- Repository-интерфейс — Spring создаёт реализацию автоматически
- DI через конструктор — Spring сам подставляет зависимости
- Generics нужны для безопасности типов
