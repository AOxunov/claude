хранить можно только Location ID; скачивать и размещать у себя фото нельзя; фото, название и

## Эндпоинты в конструкторе (на 2026-09-24)

В путях — `tripedvisor` (опечатка, но так и называются). Все три — `GET`, по одной стадии `_body`.
Ключ TripAdvisor прописан прямо в каждом эндпоинте (в заметки и git не писать).

| Путь | Стадия (id) | Handler | Что делает |
|---|---|---|---|
| `v1/tripedvisor/location/search` | `_body` (148) | `js_eval_handler` | поиск по названию + фото каждого найденного объекта |
| `v1/tripedvisor/location/nearby_search` | `_body` (147) | HTTP Request | объекты рядом с точкой, `category=hotels` жёстко |
| `v1/tripedvisor/main-datas` | `_body` (149) | HTTP Request | детали объекта по `location_id` |

HTTP Request (настройки стадии): `method`, `URL` (параметры запроса — `#lat`, `#location_id`),
`content_type`, `body`, `headers` (**обязательное поле**), переключатели `serialize_result` и
`http_response`, поле `access_condition`.

- `nearby_search`: URL `…/location/nearby_search?latLong=#lat,#lng&category=hotels&key=<ключ>`,
  в заголовках `Cookie: TACds=…; TAUnique=…` — браузерная кука сайта tripadvisor.com,
  Content API она не нужна. Видимо, вписана, чтобы заполнить обязательное поле; заменить на
  `Accept: application/json`.
- `main-datas`: URL `…/location/#location_id/details?key=<ключ>`, без `language` → только английский.

`location/search` (как было):
```js
const {lat, lng, name, category} = requestParams;
const tripadvisorKey = "<ключ>";
const fullUrl = `https://api.content.tripadvisor.com/api/v1/location/search?key=${tripadvisorKey}&searchQuery=${name}&category=${category || "restaurants"}&latLong=${lat}%252C${lng}&radius=15&radiusUnit=km&language=en`;

let res = http.get(fullUrl);
const len = res.data.length;

for (let i = 0; i < len; i++) {
    const locationId = res.data[i].location_id;
    if (!locationId) continue;

    const imgs = http.get(`https://api.content.tripadvisor.com/api/v1/location/${locationId}/photos?key=${tripadvisorKey}&limit=25`);

    if (imgs && imgs.data && imgs.data.length > 0) {
        let limitedImgs = [];
        let maxLimit = Math.min(imgs.data.length, 25);
        for (let j = 0; j < maxLimit; j++) {
            limitedImgs.push(imgs.data[j]);
        }
        res.data[i]["allImgs"] = limitedImgs;
    } else {
        res.data[i]["mainImg"] = null;
    }
}

return {res: res, fullUrl, len: len};
```

## Замечания к текущим эндпоинтам

1. **Ключ утекает в ответ.** `search` возвращает `fullUrl` — любой, кто вызовет эндпоинт,
   получит ключ. Весь смысл прокси через платформу — спрятать ключ.
2. **Ключ в тексте ошибки.** Если `http.get` упадёт, сообщение об ошибке (с URL и ключом)
   может уйти клиенту и в логи. Вызовы оборачивать в `try/catch`.
3. **Падение на ответе с ошибкой.** При неверном ключе / лимите TripAdvisor отвечает
   `{error: …}` без `data` → `res.data.length` роняет стадию.
4. **`searchQuery` не кодируется.** Пробел, `&`, `'` (`O'zbek`), кириллица в названии ломают URL.
5. **`latLong=${lat}%252C${lng}`** — запятая закодирована дважды, а в `nearby_search` стоит
   обычная запятая. Если координаты не пришли — уходит `undefined%252Cundefined`.
   Проверить, кодирует ли `http.get` URL сам (см. «Как проверить кодирование URL»).
6. **1 + N платных вызовов.** Поиск возвращает до 10 объектов, на каждый — отдельный вызов фото:
   один поиск = до 11 вызовов, выполняются последовательно (медленно).
7. **`limit=25` не работает**: фото отдаются не больше 5 на объект (так в документации Content API).
8. **Разные поля при успехе и неудаче**: `allImgs` при наличии фото, `mainImg: null` — без.
9. `category` не проверяется — в URL можно дописать свои параметры. Допустимые:
   `hotels`, `attractions`, `restaurants`, `geos`.
10. `access_condition` пуст — проверить, что эндпоинты требуют токен, иначе квоту может
    расходовать кто угодно.
11. Ключ записан в трёх местах. Вариант — хранить в `lists` и подставлять стадией `sql_select`.
12. `main-datas` без `language` — только английский. Для `name_ru` / `description_ru` нужен
    второй вызов с `language=ru`; узбекского у TripAdvisor нет → перевод (как в импортёре Booking — Gemini).

## `location/search` — исправленный вариант

Форма ответа изменена: `{data: [...], count}`, у каждого объекта `allImgs` (массив URL) и `mainImg`.

```js
const KEY = "<ключ TripAdvisor>";
const BASE = "https://api.content.tripadvisor.com/api/v1";
const CATEGORIES = ["hotels", "attractions", "restaurants", "geos"];
const MAX_PHOTOS = 5; // больше 5 фото на объект API не отдаёт

// Ошибку наружу не пробрасываем: в её тексте был бы URL с ключом
function get(url) {
    try {
        return http.get(url);
    } catch (e) {
        return null;
    }
}

function isCoord(x) {
    return /^-?\d{1,3}(\.\d+)?$/.test(String(x || ""));
}

// Самый крупный доступный размер фото
function photoUrl(photo) {
    const im = photo && photo.images;
    if (!im) return null;
    const best = im.original || im.large || im.medium || im.small;
    return best && best.url ? best.url : null;
}

const p = requestParams || {};
const name = String(p.name || "").trim();
if (!name) {
    return { data: [], count: 0, message: "name bo'sh" };
}
const category = CATEGORIES.indexOf(p.category) !== -1 ? p.category : "restaurants";

let url = BASE + "/location/search?key=" + KEY
    + "&searchQuery=" + encodeURIComponent(name)
    + "&category=" + category
    + "&language=en";

// Координаты — только если пришли обе и похожи на числа
if (isCoord(p.lat) && isCoord(p.lng)) {
    url += "&latLong=" + p.lat + "," + p.lng + "&radius=15&radiusUnit=km";
}

const res = get(url);
if (!res || !Array.isArray(res.data)) {
    return { data: [], count: 0, message: "TripAdvisor javob bermadi" };
}

const items = [];
for (let i = 0; i < res.data.length; i++) {
    const loc = res.data[i];
    if (!loc || !loc.location_id) continue;

    const photos = get(BASE + "/location/" + loc.location_id + "/photos?key=" + KEY + "&limit=" + MAX_PHOTOS);
    const imgs = [];
    if (photos && Array.isArray(photos.data)) {
        for (let j = 0; j < photos.data.length; j++) {
            const u = photoUrl(photos.data[j]);
            if (u) imgs.push(u);
        }
    }

    loc.allImgs = imgs;
    loc.mainImg = imgs.length ? imgs[0] : null;
    items.push(loc);
}

return { data: items, count: items.length };
```

### Как проверить кодирование URL

Неизвестно, кодирует ли `http.get` URL сам. Временная JS-стадия:
```js
return http.get("https://postman-echo.com/get?a=Plov Center&b=1,2&c=1%2C2");
```
В ответе `args`: если `a = "Plov Center"` и `c = "1,2"` — URL уходит как есть, значит нужен
`encodeURIComponent`, а `%252C` неверен. Если `c = "1%2C2"` — платформа кодирует сама,
тогда `encodeURIComponent` из кода убрать. Записать результат в [[platon-js-eval-runtime]].

## Задача и рекомендация (2026-09-24)

**Задача:** собрать в easy-trip как можно больше ресторанов через бесплатный API TripAdvisor.

**Рекомендация:** TripAdvisor для массового наполнения не годится. Базу собирать из
OpenStreetMap, а TripAdvisor использовать только для привязки `location_id` и показа
рейтинга со ссылкой.

Почему не TripAdvisor:
- Квота: у Terra бесплатны первые 1 000 вызовов (раз или в месяц — не выяснено). Поиск и
  `nearby_search` отдают максимум 10 результатов без пагинации; на ресторан нужно ещё
  `details` + `photos` → бесплатно выйдет несколько сотен ресторанов.
- Условия: хранить разрешено только `location_id`. Массовое копирование — ровно то, что они
  запрещают; ключ привязан к аккаунту компании. Фото — авторские права пользователей.
- Старый Content API устарел и, возможно, уже отключён.

- **API — Terra** ([[Terra-API]]), не старый Content API.
- **Города:** Ташкент, Самарканд, Бухара.
- **Язык — русский**; остальное доделывают модераторы.

- Фото — файлом через `file/api/v1/upload/form`, `fetch` с Bearer из `localStorage.auth_token`.

### Регионы — `lists`, `type_id = 1`

`lists` — общая таблица-справочник платформы (`primary key (type_id, id)`, колонки
`name1..4`, `val01..10`, `int01..10`, `num01..10`, `long01..03`, `geo_polygon json`,
`min_lon/max_lon/min_lat/max_lat`, `location`, `state`).

В `type_id = 1` — **регионы, не города**: 14 строк (12 вилоятов, Каракалпакстан, г. Ташкент) +
`id = 0` «Республика» (`state = 0`).

| Колонка | Что в ней | Пример |
|---|---|---|
| `id` | id региона | `18` |
| `name1` | узб. кириллица | Самарқанд |
| `name2` | русский | Самарканд |
| `name3` | английский | Samarkand |
| `name4` | узб. латиница | Samarqand |
| `val01` / `val02` / `val06` | полное / краткое / без «-и» название | Самарқанд вилояти |
| `val05` | slug | `samarqand` |
| `key1` | код из 2 букв | `SA` |
| `int03` | код СОАТО | `1718` |
| `num` | порядок сортировки | `8` |
| `num10` | население | `3928700` |
| `geo_polygon` | GeoJSON `Polygon` / `MultiPolygon` (lon, lat) | 34–943 точек |
| `min_lon … max_lat` | bbox | |

Регионы огромные: Навоийский ~420×480 км, Каракалпакстан ~536×505 км, г. Ташкент ~19×24 км.

### Схема (Terra)

1. **Поиск:** `catalog/locations/nearby` по прямоугольнику города, `category=RESTAURANT`,
   `size=20`, страницы по кнопке «ещё». Первая страница даёт `total_elements` — сколько всего
   ресторанов у TripAdvisor в городе. Сортировка — по рейтингу, лучшие первыми.
   Не чаще 1 запроса в секунду (общий лимит поиска).
2. **Отметка дублей:** по найденным ID — `select ta_id from places where ta_id = any(…)`.
3. **Выбор:** галочки (или «первые N»).
4. **Импорт каждого:** `locations/{id}` (`locale=ru-RU&locale=en-US`) → `locations/{id}/photos`
   (`size=5`) → `fetch` фото → `upload/form` → `POST v1/meal-place` → статус в строке.
   Оркестрирует браузер: прогресс, «Стоп», ошибка одной строки не валит остальные.
5. **Allowlist:** `locations/{id}` и `photos` отдают только объекты из allowlist (иначе 404).
   Нужно ли его вести на Discover — проверить; если да — `POST /allowlist` (APPEND) перед деталями.

Эндпоинты-прокси в конструкторе (ключ — в заголовке `X-API-Key` стадии HTTP Request):
- `v1/tripedvisor/terra/nearby` — `sw_lat`, `sw_lon`, `ne_lat`, `ne_lon`, `page`;
- `v1/tripedvisor/terra/location` — `id`;
- `v1/tripedvisor/terra/photos` — `id`;
- `v1/tripedvisor/existing` — `ids` через запятую → какие `ta_id` уже есть.
